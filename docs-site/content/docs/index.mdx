DimRead is a tray app. It warms your display's colour temperature and dims it in
software — below the floor your monitor's own brightness control allows — on
every monitor or on one, on a schedule or on a hotkey.

There is one window: **Settings**. Everything else happens from the tray icon.

## First launch

<Tabs items={["Windows", "macOS", "Linux"]}>

<Tab value="Windows">

`DimRead.exe` is an installer that pre-selects **Portable Installation
(recommended)** and puts the app in `%USERPROFILE%\Desktop\DimRead`. A portable
install keeps its settings and logs in a `Data/` folder next to the executable,
and writes no Add/Remove Programs entry, no shortcuts and no uninstaller. See
[Portable mode](/docs/general#portable-mode) for the details and for how to
move an existing install.

1. SmartScreen says *"Windows protected your PC."* Click **More info → Run
   anyway**.
2. **The settings window opens on its own**, on the **Display** tab. DimRead
   creates that window hidden and reveals it as soon as the interface has
   painted, so there is no flash of an empty rectangle — and no setting to
   start without it.
3. Closing the window does not quit: it hides DimRead to the tray. Look for the
   icon in the notification area — you may need to expand the overflow chevron
   and drag it onto the taskbar. **Left-click** it to bring the window back;
   **right-click** it for the flyout, which carries the same sliders and modes.

The zipped build needs the Microsoft Edge **WebView2** runtime, which ships with
Windows 11 and with most Windows 10 installs.

</Tab>

<Tab value="macOS">

1. Open the `.dmg` and drag **DimRead** to Applications.
2. The first launch is blocked because the app is unsigned. Right-click the app
   → **Open**, then confirm. Alternatively, run:

   ```bash
   xattr -dr com.apple.quarantine /Applications/DimRead.app
   ```

3. The settings window opens on its own. DimRead lives in the menu bar rather
   than the Dock, so closing that window leaves the app running there.

<Callout type="warn">
The macOS display backend is **alpha**. Colour temperature and brightness apply,
but per-app rules and the window effects are not wired to a native
implementation yet — see [Platform support](/docs/troubleshooting#platform-support).
</Callout>

</Tab>

<Tab value="Linux">

The AppImage is the fastest path:

```bash
chmod +x DimRead_0.0.4-alpha_amd64.AppImage
./DimRead_0.0.4-alpha_amd64.AppImage
```

For the `.deb` / `.rpm`, install the tray dependency first — DimRead's only
visible surface is the tray icon, and without an AppIndicator host you will have
no way to reach it:

```bash
sudo apt install libayatana-appindicator3-1
```

<Callout type="warn">
**Your compositor decides whether the filter works.** X11 sessions are fine. On
Wayland, DimRead drives the `zwlr_gamma_control_v1` protocol, which the
wlroots family implements — sway, Hyprland, river, labwc. GNOME's Mutter and
KDE's KWin do not expose it, so on those the sliders move and the screen does
not change. See
[Nothing happens on Wayland](/docs/troubleshooting#nothing-happens-on-wayland).
</Callout>

</Tab>

</Tabs>

## Your first dim

<Steps>

<Step>

**Find the window.** It is already open on the **Display** tab after a fresh
launch. If you closed it, left-click the tray icon to bring it back —
right-click gets you the flyout instead, the same controls without the window.

</Step>

<Step>

**Pick a mode.** The eight buttons at the bottom of Quick controls are presets.
Click **Reading** — 5500 K at 85% brightness. The screen warms immediately.

</Step>

<Step>

**Adjust.** Drag the temperature slider left to warm further. The readout above
the sliders shows the exact Kelvin and percentage being applied.

</Step>

<Step>

**Check the schedule.** **Auto day/night** is already on, and the time source
already defaults to **Automatic** — DimRead works your sunrise and sunset out
from the system timezone, offline, with no location permission prompt. Open the
[Schedule](/docs/schedule) tab and read the **Detected location** line to see
which city it settled on and what times it derived. Everything from here is
correcting that guess, not switching the feature on.

</Step>

<Step>

**Bind a hotkey.** Open the [Hotkeys](/docs/hotkeys) tab, click the record
button on the **Toggle blue-light filter** row, and press a combination. It arms
immediately — no restart.

</Step>

</Steps>
