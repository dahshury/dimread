**Settings → General** is the tab about the app rather than about your screen.
It's short on purpose: two sections, four rows — how DimRead starts, what the
close button does, which language it speaks, and whether it animates. Nothing
here needs a restart.

This page is also where the docs keep the canonical file paths. If another page
tells you to open a log or delete a settings file, the exact location is in
[Where DimRead keeps its files](#where-dimread-keeps-its-files) below.

## Startup & tray

### Start at login

Registers DimRead with your OS's launch-at-login mechanism so the filter and its
schedule are running before you open anything. **Default: off.**

Each platform gets a different entry, all named `DimRead`:

| OS | Where the entry lands |
| --- | --- |
| Windows | `HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run` |
| macOS | `~/Library/LaunchAgents/DimRead.plist` — it shows up under *Allow in the Background*, not *Open at Login* |
| Linux | `~/.config/autostart/DimRead.desktop` — the path is hard-coded, so `$XDG_CONFIG_HOME` is ignored |

DimRead reconciles the toggle with the OS after the save lands **and again at
every startup**, so an entry another tool wiped comes back on its own.

**Note:** on Linux, compositors that don't run XDG autostart entries — sway,
Hyprland, river — ignore the desktop file, and the toggle has no effect there.

### Minimize to tray

Decides what the window's close button does: hide DimRead to the tray, or quit
it. **Default: on.** Alt+F4 and the taskbar close take the same path, so the two
can never drift apart.

<Callout type="warn">
With this **off**, the X button quits DimRead — which restores your monitors'
original gamma and drops the filter. <Kbd>Esc</Kbd> is the exception: it hides
the window and nothing more, whatever this toggle says, so a reflex keypress
can't take your filter down with it.
</Callout>

That's the whole section. There's no theme picker (DimRead's own UI is
permanently dark), no start-minimized row, and no update setting — the update
check lives on [About](/docs/about).

## Appearance

Both rows carry a reset arrow that restores the shipped default behind a
confirm dialog (*"Restore this setting to its default value?"*). The arrow is
greyed out while the setting is already at its default.

### Language

Picks the UI locale. **Default: English** — and English is the only option that
ships today, so the picker proves the plumbing works rather than offering a
choice you can act on. Adding a locale means dropping a message bundle into
`messages/` in the source tree and rebuilding. The choice applies immediately,
with no restart.

### Reduce motion

Force-reduces DimRead's animations even when your OS isn't asking for reduced
motion. **Default: off** — DimRead honours the OS preference in that state.
Turn it on if the window's open and close animations bother you but you don't
want to change anything system-wide. Applies instantly.

## Portable mode

DimRead decides it is portable **at startup, before Tauri initialises**, by
looking for a file named exactly `portable` (no extension) next to the
executable. The file must contain the magic string `DimRead Portable Mode` —
surrounding whitespace is fine, but an empty or unrelated `portable` file does
**not** count. That's deliberate: a stray file dropped by a package manager
can't silently move your data.

When the marker is valid, DimRead creates a `Data/` folder beside the executable
and puts everything there instead of in the OS app-data directory.

On Windows this is the default experience. The installer `DimRead.exe`
pre-selects **Portable Installation (recommended)** and installs to
`%USERPROFILE%\Desktop\DimRead`; that install writes no Add/Remove Programs
entry, no Start Menu or desktop shortcut, no file associations and no
uninstaller. `DimRead-portable.zip` ships the same marker already in place.

<Callout type="info">
**"No registry writes" describes the install, not the running app.** Turning on
**Start at login** still writes the `Run` value described above, and
[System theme](/docs/schedule#system-theme) writes the Windows theme keys while
it is set to anything but **Disable**. Crash reports always go to
`%TEMP%\dimread-crash-<timestamp>.log` regardless of portable mode. The tray
*reads* your Windows theme key to pick a light or dark glyph, but never writes
it.
</Callout>

### Converting an install to portable

<Steps>

<Step>

**Quit DimRead** from the tray flyout — not merely hide it — so nothing is
holding the settings file.

</Step>

<Step>

**Create the marker.** Next to the executable, make a file named `portable` with
`DimRead Portable Mode` as its first line.

</Step>

<Step>

**Bring your settings across** (optional). Create a `Data` folder beside the
executable and copy `dimread-settings.json` into it from the path in the table
below. Skip this and DimRead starts from defaults; the old file stays put.

</Step>

<Step>

**Relaunch.** DimRead creates `Data/` if it isn't there and writes everything
inside it from then on. Delete the marker to go back.

</Step>

</Steps>

The detection code has no platform branches, so a marker next to the binary
works on macOS and Linux too — but nothing in their packaging creates one, and
inside a `.app` bundle "next to the binary" means `DimRead.app/Contents/MacOS/`.
In practice, portable mode is a Windows story.

## Where DimRead keeps its files

Everything lives in one directory per platform, named after the bundle
identifier `com.dahshury.dimread`. Logs are the exception on Windows and macOS,
which put them somewhere else.

| What | Windows | macOS | Linux |
| --- | --- | --- | --- |
| Settings | `%APPDATA%\com.dahshury.dimread\dimread-settings.json` | `~/Library/Application Support/com.dahshury.dimread/dimread-settings.json` | `~/.local/share/com.dahshury.dimread/dimread-settings.json` |
| Settings backup | `…\dimread-settings.json.bak` | `…/dimread-settings.json.bak` | `…/dimread-settings.json.bak` |
| Log file | `%LOCALAPPDATA%\com.dahshury.dimread\logs\dimread.log` | `~/Library/Logs/com.dahshury.dimread/dimread.log` | `~/.local/share/com.dahshury.dimread/logs/dimread.log` |
| Window position | `…\window-state.json` | `…/window-state.json` | `…/window-state.json` |
| Shutdown journal | `…\dimread-session-guard.json` | `…/dimread-session-guard.json` | `…/dimread-session-guard.json` |
| Crash report | `%TEMP%\dimread-crash-<ms>.log` | `$TMPDIR/dimread-crash-<ms>.log` | `/tmp/dimread-crash-<ms>.log` |

`…` means the same directory as the Settings row above it. On Linux both
directories follow `$XDG_DATA_HOME` when you've set it; `~/.local/share` is the
default.

**In portable mode** every one of those files except the crash report moves next
to the executable:

```
dimread.exe        (named DimRead.exe inside DimRead-portable.zip)
portable
Data\
  dimread-settings.json
  dimread-settings.json.bak
  dimread-session-guard.json
  window-state.json
  logs\dimread.log
  webview\
```

A few notes on what you'll find there:

- **`dimread-settings.json`** — the whole settings tree. Writes are atomic
  (temp file, fsync, rename); a `.tmp` sibling only exists mid-write.
- **`dimread-settings.json.bak`** — refreshed after every successful write. If
  the main file is ever unreadable DimRead falls back to defaults, and the
  `.bak` is there for you to restore by hand.
- **`dimread-session-guard.json`** — present only while DimRead is running. If
  it's there at startup, the previous run died without restoring your gamma, and
  DimRead repairs it.
- **`dimread.log`** — Info level in release builds, local timestamps, capped at
  500,000 bytes. At the cap the old file is **deleted, not rotated**, so there
  is only ever one log. See [Diagnostics](/docs/diagnostics).

## Uninstalling

### Windows — portable (the default)

Quit DimRead from the tray, then delete the install folder. That takes the
binary, the `portable` marker and all of `Data\` with it. Two things survive,
because a portable install has no uninstaller to clean them up:

- the `HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run` value named `DimRead`, if you ever turned on **Start at login**
- any `%TEMP%\dimread-crash-*.log` files

### Windows — normal install

Only reachable if you chose **Normal Installation** in the wizard. Use
**Settings → Apps → DimRead → Uninstall**, or run `uninstall.exe` from the
install folder. Tick **Delete the application data** on the confirm page to
also remove `%APPDATA%\com.dahshury.dimread` and
`%LOCALAPPDATA%\com.dahshury.dimread`.
The uninstaller removes the shortcuts, the Add/Remove Programs entry and the
`Run` value for you.

### macOS

Quit DimRead, drag `DimRead.app` to the Trash, then delete
`~/Library/Application Support/com.dahshury.dimread`,
`~/Library/Logs/com.dahshury.dimread` and — if you used **Start at login** —
`~/Library/LaunchAgents/DimRead.plist`.

### Linux

Remove the package (`sudo apt remove …` / `sudo dnf remove …`), or delete the
AppImage file. The Debian and RPM package names are lowercase and differ from
the download file name, so confirm yours with `dpkg -l | grep -i dimread` or
`rpm -qa | grep -i dimread` first. Then remove
`~/.local/share/com.dahshury.dimread` and, if you used **Start at login**,
`~/.config/autostart/DimRead.desktop`.
